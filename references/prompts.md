# 提示词与工作流模板

综合原始教程文档的完整提示词体系，按当前已验证实现（混合多球、连续主球轨迹、无大面积光晕、Chrome/Edge 本地渲染）更新。直接复制给 Agent 使用，方括号处填写实际值。

## 一、环境准备提示词

开始制作前先跑这一步，确保环境就绪、最小验证通过，不要只看版本号：

```markdown
先不要制作动画，请先检查并准备 Remotion 3D 曲谱动画所需的环境。

1. 检查项目模板
使用 huige-music 技能的 assets/music-score-starter 模板建立项目（依赖版本已锁定：
Remotion 4.0.518 + React Three Fiber + Three.js + Verovio，所有 @remotion 包必须同版本）。
检查 Node.js 与 npm、FFmpeg/FFprobe、Python3（仅标准库脚本用）。

2. 浏览器（禁止下载 Chrome Headless Shell）
渲染一律用本地浏览器：Chrome 优先（C:/Program Files/Google/Chrome/Application/chrome.exe），
没装 Chrome 用 Edge（C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe）。

3. 素材检查
- 曲谱 .mxl 与 MIDI .mid 必须核对同源性：对比音符数、拍位序列、声部分布，
  不一致就报告并换源，禁止硬凑映射。
- 如提供真人音频，先验证与 MIDI 同步；不同步则用同一 MIDI 合成音轨替代。

4. 最小验证（不要只检查版本号）
- 项目能编译（npm run typecheck）；
- 渲染一个约 1 秒、低分辨率的简单 3D 测试视频，验证浏览器、WebGL 和视频导出；
- 如果素材已提供，尝试解析 MIDI 并将 MXL 渲染为 SVG。

5. 需要安装的按需依赖
- fluidsynth + .sf2 音源（合成钢琴音轨时才装，Windows 用 GitHub release 二进制）；
- 不要一次安装大量无关工具。

遇到失败时，先定位并修复具体错误，不要反复盲目重装。
最后简短汇报：哪些已具备、哪些新安装、验证是否通过、是否还有阻塞。
```

## 二、简单版提示词（首选，适合已跑通环境后直接出片）

```markdown
/huige-music

请根据参考视频（如有），制作「两个发光小球在真实曲谱上跳跃演奏，镜头沿曲谱滑行」的
3D 音乐动画，并完成可运行项目和 MP4 导出。

素材目录：[填写路径]
我已准备参考视频、MXL/MusicXML 曲谱、MIDI，以及可选的演奏音频。先检查实际文件与
参考效果，再自主完成制作。时长根据素材和需求确定。

技术使用技能模板（Remotion + React Three Fiber/Three.js）。曲谱通过 Verovio 从 MXL
生成 SVG，不能用截图代替解析。

核心要求：

1. 准确对应音符
MXL 负责谱面，MIDI 负责时间轴。将 MIDI 事件映射到渲染后真实符头坐标，禁止均匀铺点
或根据音量乱跳。所有声部、和弦音都要有反馈；区分新起音与延音，不漏音、不重复发声。
映射结果必须零未匹配（兜底匹配需逐级计数报告）。

2. 混合多球与连续跳跃
每个声部一颗主球贯穿全曲，轨迹线全片连续；和弦音符自动分出副球各落一个符头，副球随
音值结束淡出。用相邻落点之间的完整时间完成低矮跳跃，准确踩中音符时刻，落地后立即起跳。
不能「停一会儿，再快速赶到下一点」。同位置重复演奏也要原地跳跃。

3. 自然入场
每颗球在自己的首音前约 0.15 秒低空渐显并持续下落，首音响起时恰好落地。必要时整体顺延
音乐与事件，不能让球提前停在音符上等待。

4. 演奏反馈
落点生成细发光圆环，轻微扩张后逐渐淡出；主球飞行带细轨迹线。和弦全部音符同步亮环。
球带贴身小光晕即可，禁止纸面大面积彩光。

5. 镜头与光照
真实 3D 低角度透视，镜头沿阅读方向平滑跟随，换行=行尾停0.3秒+0.55秒斜扫，翻页同理。
取景足够近，让演奏中的上下谱表成为主体，手机上也能看清「球落到哪个音符」。
整体暗调但谱面清晰，适量 Bloom、轻微景深和暗角，避免大光斑、强烈霓虹和粒子特效。

6. 音画同步
MIDI 是唯一时间源。固定偏移可校正；速度不同或明显漂移时改用同一 MIDI 生成的钢琴音轨。
以准确同步为优先，不靠听感猜时间。

完成后检查完整视频的落点、漏音、构图、谱面可读性和导出音轨同步，交付源码、最终 MP4
及简短运行说明。不要只给方案或代码片段。
```

## 三、详细版提示词（含分析阶段，适合新曲第一遍或效果不对时排查）

```markdown
/huige-music

请在以下目录中制作 Remotion 动画：[填写路径]
目标是「发光小球在真实曲谱上弹奏，镜头沿曲谱滑行」的 3D 音乐可视化动画。
目录中已有：参考视频（可选）、.mxl 曲谱、.mid 文件、演奏音频（可选）。
先检查实际文件名和内容，不要假设固定文件名。

### 第一阶段：先分析，不要盲目开始制作

1. 读取参考视频（如有）的尺寸、FPS、时长，分析前 10 秒的运动：透视角度、镜头移动
   方向与速度、是否有 zoom/dolly、景深范围、两色球分别位于哪个声部、当前音与历史音
   的亮度/大小/透明度差异。
2. 解析 .mxl：小节、staff/voice、notes、duration、pitch、谱面结构。
3. 解析 .mid：tempo map、note on/off、onset 时间、时值、力度、轨道。
4. 检查 MIDI 与 MXL 是否同源可对齐：音符数量与顺序、起始位置、节拍。
5. 检查音频与 MIDI 是否对应。节奏明显不同时，以 MIDI 时间轴为准并报告差异。

### 技术方案

Remotion + React Three Fiber + Three.js postprocessing。曲谱由 Verovio 渲染 SVG，
不得截图替代。数据职责：MXL 管视觉结构，MIDI 管时间轴，音频只做配音候选。

### 画面目标

- 真实曲谱平铺 3D 空间，整体稍倾斜，相机低角度贴谱滑行；
- 当前演奏区域画面中央偏下，镜头持续平滑推进，不跳镜、不抖动、不快速 zoom；
- 感觉是「摄像机沿着正在被演奏的曲谱缓慢滑行」。

### 音符轨迹

- 上声部柔紫球、下声部暖橙球；球体小、核心清晰、贴身光晕克制，禁止纸面大面积彩光；
- 每个起音触发发光圆环：亮度快速提升→轻微放大→3.6 秒内淡出；历史环逐渐衰减；
- 主球轨迹线全片连续；和弦副球分落其他符头后随音值淡出；
- 禁止：上下弹跳的大球、等化器、柱状频谱、粒子爆炸、赛博朋克霓虹、音符飞离谱面很高。

### 镜头与景深

初始低角度俯视，带明显透视，沿阅读方向推进，根据当前演奏小节持续跟随，运动顺滑连续。
轻微景深：当前演奏位置最清晰，前后略虚化。加 subtle vignette、bloom、少量 filmic
contrast。不加颗粒、色差、扫描线。

### 音符位置映射（本实验的核心）

发光音符必须落在实际曲谱对应音符的位置附近，禁止凭感觉均匀排线。建立：
`MIDI note event → MXL 对应 note → rendered note coordinate → Three.js world coordinate`
映射存在歧义时优先保证开头段落的主音符正确，并逐级报告兜底计数。

### 时间同步策略

严格按优先级：1) MIDI 做时间源 2) MXL 提供结构与布局 3) 最后才对齐真人音频。
音频与 MIDI：固定 offset→整体平移；tempo 漂移→禁止硬贴；rubato 明显→改用 MIDI 合成
音轨。正确性优先级：MIDI 驱动动画正确 > 保留真人音频。

### 第一版范围

只做前 10 秒验证四个核心问题：曲谱能否正确渲染；MIDI 事件能否读取；能否映射到实际
符头坐标；3D 镜头+发光轨迹能否接近参考视频。不要提前做复杂 UI、参数面板、过多抽象。

### 输出要求

独立 Composition（MusicScoreVisualizer，1920×1080/30fps）。完成后：
1. 渲染预览 MP4；2. 说明 MXL 渲染方式；3. 说明 MIDI 如何驱动画面；4. 说明音符位置
映射方法与未匹配报告；5. 说明音频是否同步及差异类型（固定偏移/tempo 不同/rubato/版本
不同）；6. 不自行扩大任务范围；7. 遇到阻塞优先保证：可运行的短片段原型、音符位置
基本正确、镜头和视觉语言接近参考。

### 额外约束（禁止的偷懒实现）

- 只在曲谱上均匀铺点按时间点亮
- 不解析 MIDI，只根据音频音量乱跳
- 不解析 MXL，只把曲谱当背景图
- 用 2D 平面替代 3D 镜头运动
- 做成通用「音乐可视化」而不是「曲谱被演奏」的感觉

最终目标：音乐正在纸面曲谱上被点亮、被演奏、被镜头追随的 3D 视觉。
```

## 四、提示词使用建议

- 先选曲谱前 10 秒左右跑通，效果满意再做全曲。
- 参考视频对照（详细版第一阶段）在「复刻别人的效果」时最有用；自己创作可跳过。
- 简单版日常够用；出现映射错误、换行跳变、和弦异常时，用详细版让 Agent 先分析再动手。
- 提示词仅供参考，不同模型表现不同，请根据实际效果调整。
